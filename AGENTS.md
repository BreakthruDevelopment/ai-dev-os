# AI Dev OS: rules for every agent

This repo is the operating system for the **30 apps in 30 days** build: who does what, how work moves, and the
rules every AI tool follows. Claude Code, Codex, Grok Build, Antigravity and Grok Bot all read this file.

**New to the project?** Read [`BRIEFING.md`](BRIEFING.md) first: what we're building, every decision in force,
and what's been dropped.

## 1. Repo safety (non-negotiable)

The BreakthruDevelopment org holds other, unrelated applications that must never change.

- Touch only repos with the GitHub topic `30-apps-30-days`. Anything else is read-only.
- Before creating a repo, list existing names. If the name is taken, **stop and ask**; never reuse or rename.
- Never force-push, delete, rename, transfer or archive a repo or branch.
- Never push to `main`. Work on `<harness>/<task>` branches (`claude/…`, `codex/…`, `grok/…`, `antigravity/…`) and open a PR.
- Never commit or paste secrets. Keys go into GitHub Actions secrets or a cloud secret manager, entered by Michael.
- Merges to `main` are Michael's call.

## 2. Models, harnesses and agents

| Layer | What it is | Here |
| --- | --- | --- |
| **Model** | The LLM doing the thinking | Claude (Opus, Sonnet), OpenAI's Codex models, Grok, Gemini |
| **Harness** | The program that wraps a model so it can read files, run commands and open PRs; each has a subscription with its own usage limits | Claude Code, Codex, Grok Build, Antigravity, Grok Bot |
| **Agent** | A role (instructions, allowed tools, a goal) running inside a harness | The files in `roles/` |

One harness can run many agents, and any role can run in any harness that has capacity. Roles are defined once,
in `roles/`, as plain instructions. Claude Code gets them as subagents in `.claude/agents/`, generated by
`scripts/sync-claude-agents.py`; edit the role file, never the generated one.

| Harness | Subscription | Starts work when | Usually does |
| --- | --- | --- | --- |
| Claude Code | Claude | An issue is labelled `claude` (sessions, or scheduled tasks overnight) | Planner, reviewer, AI builder, deploys, template changes |
| Codex | ChatGPT Plus (tightest limits) | An issue is labelled `codex` | Fullstack on selected issues; second review on security-sensitive PRs |
| Grok Build | X (SuperGrok) | Michael runs `scripts/run-harness.sh grok` on his Mac | UI pages, fullstack issues, READMEs (used more from 2026-11-09) |
| Antigravity | Google AI Pro | Michael runs `scripts/run-harness.sh antigravity` on his Mac | Fullstack and docs (on trial) |
| Grok Bot | X (Grok) | Michael sends it an app's README and live URL | Launch posts and demo scripts; no repo access (below) |

Grok Build and Antigravity are CLIs on Michael's Mac, not GitHub apps: labels don't trigger them, the runner
script does ([`runbooks/harnesses-on-mac.md`](runbooks/harnesses-on-mac.md)). Jules is gone: Google turns it
read-only after 2026-11-11 and shuts it down on 2026-12-31; Antigravity replaces it.

| Role (`roles/`) | Default harness | Can move to |
| --- | --- | --- |
| `planner` | Claude Code | — |
| `fullstack-builder` | Grok Build; Codex or Antigravity on the issues assigned to them; Claude Code for template changes | Claude Code, Codex, Antigravity |
| `ai-builder` | Claude Code | Antigravity, Grok Build |
| `ui-builder` | Grok Build | Antigravity, Claude Code |
| `reviewer` | Claude Code on every PR, plus Codex on security-sensitive PRs | — |
| `devops` | Claude Code | any (Terraform changes in `30-apps-infra`: Grok Build or Antigravity) |
| `docs-writer` | Grok Build | Antigravity, any |
| `ops-monitor` | Claude Code scheduled task (nightly, 5:37 AM Central, posts to the `Ops report (nightly)` issue in this repo) | Claude Code session |

**Grok Bot's job.** It can't push code and holds no secrets, so it does the build-in-public work: when an app goes
live, Michael pastes its README and live URL into Grok Bot, which drafts an X post and a LinkedIn post (problem,
what the app does, the AI feature, cloud, link, no invented numbers) and a two-minute demo script (the clicks in
order and what each proves). Michael edits and posts them himself; Grok Bot never posts or opens accounts. It no
longer runs the ops monitor.

## 3. GitHub is the single source of truth

Harnesses never talk to each other directly. Work moves through:

| Thing | Where |
| --- | --- |
| What to build | `catalog.yaml` (this repo) and the app's spec at `specs/NN-slug.md` |
| The queue | One GitHub Project board across every app repo |
| Work items | Issues, each with a role in the title (`[ui-builder] Dashboard page`) and a harness label: `claude`, `codex`, `grok` or `antigravity` |
| Changes | Pull requests from `<harness>/<task>` branches |
| Status | PR checks, the board, and the Build Tracker (app 1) |
| What happened | A run log per app in `runs/NN-slug.md` |

**The harness label is the start signal.** Claude adds an issue's harness label only once the issues it depends
on are merged; until then its planned owner is in the spec. **Pick up only issues with your
harness's label**, and read the role file named in the title before starting. (`jules` labels may linger on old
repos; nobody picks them up.)
When a harness hits its usage limit, Michael (or the planner) relabels its open issues; nobody buys extra credits.

## 4. Daily flow

1. **Planner** writes `specs/NN-slug.md` from `templates/spec.md`, opens one issue per slice with a role and a harness label, and adds them to the board.
2. **Builders** open PRs against the app repo.
3. **Reviewer** reviews each PR; Codex adds a second review on security-sensitive ones. CI must be green: lint, typecheck, tests, build, smoke.
4. **DevOps** adds the app to `apps.yaml` in `30-apps-infra` for the day's `live_cloud` (a PR Michael merges; AWS runs from CloudShell), then runs the smoke test against the live URL. Migrations run when the app starts.
5. **Docs writer** fills in the README from `templates/app-readme.md`. Grok Bot drafts the launch posts and demo script from it.
6. **Michael** reviews, merges and posts the app. DNS records are created in Cloudflare by Terraform on deploy
   (`30-apps-infra` README, "Custom domains and DNS"); nobody adds them by hand.
7. **Overnight:** Codex and scheduled Claude Code tasks work queued issues into PRs; Grok Build and Antigravity work theirs whenever Michael starts the runner on his Mac. The ops monitor (a scheduled Claude Code task) posts to the `Ops report (nightly)` issue. Nothing merges without Michael.

## 5. Usage limits

All four subscriptions (Claude, ChatGPT Plus, X, Google AI Pro) have rolling limits; Codex's are the tightest, so
it gets only selected issues. Within Claude Code, roles run one after another, not in parallel.
Spread work by moving issues between harnesses, not by buying credits.
