Decided by Michael on 2026-11-19. Fourteen catalog slots stop being business web apps and become **demonstrations
for a Caylent interview on 2026-12-01**. Build target: **Tuesday 2026-11-24**, leaving a week for tweaks and
documentation.

## What changed and why

| | Before | Now |
| --- | --- | --- |
| Slots | 17–29 and 32: SaaS-style web apps on four clouds | Fourteen demos: tools, libraries and small services |
| Cloud | Rotation across AWS, Azure, Google Cloud, Oracle | All on **AWS**, in a **second AWS account** Michael created for this |
| Model | Gemini free tier through `generate()` | **Amazon Bedrock** (Claude models) where a model is needed |
| Stack | Next.js from `30-apps-template` | **Python**, importing one shared library (app 17) |
| Purpose | Roadmap coverage | Object-oriented design applied to agents, and the Claude Certified Architect body of knowledge |

Three sources set the shape:

- **Joshua Morley's post on object-oriented design for agentic systems.** It maps fourteen patterns onto agents but
  has no code and nothing specific to language models, and it warns about over-engineering. So every pattern here has
  to solve a real agent problem, and the catalog entry says which.
- **The Claude Certified Architect (Foundations) exam guide.** Five domains, thirty task statements, six scenarios.
  All six scenarios are built as running systems.
- **Caylent's postings** for Forward Deployed Engineer, Senior Forward Deployed Engineer and Forward Deployed AI Lead.
  They ask for three things repeatedly: turn ambiguity into scoped work, ship software that runs after you leave,
  and leave a reusable artifact behind. The AI Lead posting lists "Certified Claude Architect" as required.

## Shared rules for the track

These replace the Next.js stack rules for these fourteen repos only. Each repo's `AGENTS.md` carries them.

- **Python 3.12**, `uv`, `ruff`, `mypy --strict`, `pytest`. The required check keeps the name
  `Lint, test, build, smoke` so the review gate and the merge rules work unchanged.
- **Every model call goes through app 17's `ModelProvider`.** No demo calls Bedrock directly.
- **Every demo runs with no model spend** on recorded replies (`ReplayProvider`), which is what CI and a default
  demo use. `--live` switches to Bedrock.
- **Writes are staged.** A tool that changes anything returns a staged change that a person approves; nothing is
  written on the model's say-so.
- **Tool results are data.** Text that comes back from a tool is never treated as instructions.
- **Each README maps its patterns and exam task statements to file and line**, so a reader can check the claim.
